# Invisible Break — Agent Instructions

## The Closed Loop

This repo is part of a **closed-loop verification system** with Kane CLI:

1. The **watcher** (`src/lib/watcher/`) runs Kane CLI test flows against the local app.
2. When Kane finds invisible breaks (console errors, 5xx responses), it generates `watcher-output/failure.md`.
3. **You (the agent)** read `failure.md`, fix the code, and save.
4. The watcher detects the save and re-runs Kane automatically.
5. If the fix works, the dashboard goes green.

## How to fix invisible breaks

When you read `watcher-output/failure.md`:

1. **Identify the break type** from the evidence signals:
   - `console_error`: A JavaScript error in the browser console. Fix by adding null checks, try/catch, or correcting the code path.
   - `http_error_response`: A server-side API returning 5xx. Fix by correcting the endpoint logic, adding a fallback, or mocking the missing service.
   - `network_error`: A failed network request. Fix by correcting the URL or adding error handling.

2. **Locate the source** using the evidence excerpt and step number:
   - Console errors usually come from `src/app/checkout/CheckoutForm.tsx` (client-side `useEffect`).
   - 5xx errors usually come from `src/app/api/*/route.ts` (server-side API routes).

3. **Fix the code** — make the minimum change needed to resolve the break:
   - For missing config: add a safe default or guard with `?.` and `??`.
   - For 500s: return a valid response instead of throwing, or fix the upstream service URL.

4. **Save the file** — the watcher will detect the change and re-run Kane.
5. **Check the dashboard** at http://localhost:3000/dashboard to see if the run passes.

## What NOT to do

- Do NOT delete or modify `kane-tests/checkout_flow_test.md` — that's the test spec.
- Do NOT delete `kane-tests/output-checkout_flow/` — those are committed Kane recordings.
- Do NOT delete `.testmuai/evidence/` — those are evidence packs.
- Do NOT modify `watcher-output/failure.md` — it's generated by the watcher.
- Do NOT disable the DevTools assertions in the test flow.

## Verification

After fixing, verify with:
```bash
npm run watch:run    # replay mode (free, uses committed recordings)
npm run watch:fresh  # fresh authoring (costs credits, but catches live breaks)
```

The dashboard at `/dashboard` shows the current state in real-time.
